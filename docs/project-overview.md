# Proactive Project Handoff

**Публичное описание проекта**  
**Дата:** 24.11.2026  
**Текущая версия плагина:** v0.1.2  
**Последняя проверенная поведенческая версия Skill:** v0.1.1  
**Регрессионная приёмка v0.1.2:** NOT_RUN

## Назначение

Proactive Project Handoff — пользовательский Skill для ChatGPT, предназначенный для повышения непрерывности длительной проектной работы между чатами.

Он помогает модели своевременно фиксировать важный контекст, поддерживать логические контрольные точки и готовить переносимые документы HANDOFF, чтобы новый чат мог восстановить проект без повторного сбора уже известных сведений.

Ключевой принцип проекта:

> Автоматизировать сохранение состояния, а не принятие решений и не выполнение следующего этапа за пользователя.

## Проблема

В длительных диалогах проектные решения, ограничения, технические детали и результаты проверок постепенно распределяются по большой истории. При переходе в новый чат часть контекста может оказаться недоступной или быть восстановлена неточно.

Обычная просьба «сделай краткое резюме» не всегда сохраняет:
- точные утверждённые решения и их статусы;
- ограничения и запреты;
- доказательства выполненной работы;
- неизвестные и непроверенные сведения;
- конфликты источников;
- точную точку остановки;
- границу между следующим шагом и разрешением его выполнять.

Proactive Project Handoff задаёт структурированную методику работы с этими сведениями.

## Основные возможности

- **Proactive Monitoring:** качественная оценка риска потери существенного контекста.
- **Checkpoint:** актуализация компактного логического состояния проекта.
- **Prepare Handoff:** подготовка полного переносимого HANDOFF.
- **Update Handoff:** актуализация ранее подготовленного HANDOFF с сохранением истории изменений.
- **Resume from Handoff:** восстановление проектного состояния в новом чате.
- **Compact Handoff:** сокращение объёма без потери критически важных сведений.
- **Completeness Validation:** проверка полноты, согласованности и доказательности HANDOFF.

## Принципиальные границы

Проект не позиционируется как автономный фоновый агент или внешняя система хранения.

Skill:
- не получает гарантированно точный процент заполнения контекстного окна;
- не имеет гарантированного доступа к внутренним событиям сжатия или завершения чата;
- не работает гарантированно в фоне между сообщениями;
- не гарантирует запуск перед исчерпанием контекста;
- не сохраняет документы автоматически в Git, Library или файловую систему без доступного инструмента и подтверждённой операции записи;
- не заменяет источники истины проекта и не отменяет проверку документов.

Уровни риска L0–L3 являются качественной оценкой модели, а не телеметрией платформы.

## Контроль пользовательских полномочий

Одна из центральных функций методики — Explicit Task Boundary.

HANDOFF, checkpoint и список открытых задач описывают состояние проекта, но не являются разрешением на выполнение работ.

Различаются состояния следующего шага:
- `NEXT_STEP_IDENTIFIED` — шаг определён;
- `NEXT_STEP_PROPOSED` — шаг предложен;
- `NEXT_STEP_AUTHORIZED` — пользователь явно разрешил выполнение;
- `NEXT_STEP_COMPLETED` — разрешённая работа выполнена.

Если пользователь просит только восстановить контекст, модель должна восстановить состояние, показать точку продолжения и остановиться. Следующий этап начинается только после соответствующего поручения.

## Платформенная совместимость

Текущая реализация проекта — Skill для ChatGPT.

Методика может быть адаптирована для других ИИ-платформ, поддерживающих системные инструкции, пользовательские Skills или агентные механизмы. Однако такая адаптация потребует переноса инструкций, настройки доступных инструментов и отдельной проверки поведения.

Нельзя считать, что текущий Skill автоматически устанавливается или работает в других ИИ-системах. Результаты тестирования ChatGPT не переносятся на другие платформы без самостоятельной приёмки.

## Проверка поведения

Для версии v0.1.1 проведена серия R1–R7 по дефекту T2-01 — Unauthorized Stage Advancement.

**Зафиксированный результат:** 7 PASS / 0 FAIL по представленным сценариям.

Проверялись:
- восстановление проектного контекста;
- сохранение решений и ограничений;
- отсутствие самовольного перехода к следующему этапу;
- сохранение исходной контрольной точки;
- выполнение ограниченного следующего этапа после явного поручения.

Результат является поведенческой приёмкой конкретной серии тестов. Он не является независимым аудитом исходного кода, forensic-проверкой внешних побочных эффектов или Security Admission.

Подробности: [отчёт приёмки T2-01, v0.1.1](acceptance/2026-11-24-t2-01-acceptance-report-v0.1.1.md).

## Для кого проект

- для пользователей, ведущих длительные технические и исследовательские проекты в ChatGPT;
- для архитекторов и разработчиков, которым важно сохранять решения и границы работ;
- для пользователей, переносящих проект между чатами;
- для команд, которым нужна дисциплина фиксации статусов и доказательств, но которые сохраняют человеческое управление действиями.
